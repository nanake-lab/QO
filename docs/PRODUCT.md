# QO 产品定义

## 一句话
QO 是一个在本机运行的服务，替你驱动各家编程 agent，并把它们在干什么、要批准什么、用了多少，集中到一处。

## 谁用
- 同时开很多 agent 会话、经常找不到哪个是哪个的人。
- 需要派活给编程 agent 的程序，例如 Nemu。

## 第一版做什么
- 按任务开会话：给任务起名、分组，一个任务可以有多个会话。
- 看流式输出和每个会话的状态：在跑、等你输入、等批准、完成、失败、已取消。
- 审批：agent 要执行命令或改文件时，原样展示要做的事，由创建这件任务的客户端决定批不批。
- 中途追加指令、打断、取消。
- 看用量：按会话和模型档位统计。
- 断线或重启以后，客户端能按游标把错过的事件补回来。

## 第一版不做
- 跨模型的记忆。
- 自动规划、自动派活。
- 云端部署、多人协作。
- 第二家 harness：第一版只接 Codex，第二家等第一家稳定以后再接。

## 边界
- QO 只为自带的界面登记任务归属。外部客户端凭每个任务的密钥恢复控制，QO 不保存它们的身份或记忆。对 Nemu 来说，QO 只是一个帮手：接活、报进度、交结果。Nemu 的记忆、权限和决定都留在 Nemu 那边。
- 谁创建的任务，谁决定它的审批。QO 的界面能看所有任务，但不能替别的客户端批准它的任务。
- QO 默认不自动批准任何操作。
- 桌面壳和浏览器共用网页。关闭桌面窗口后，服务继续在后台运行，可以从托盘重新打开窗口。关掉浏览器页面后，从托盘选「在浏览器中打开」或运行 `qo open` 即可重新登录。
- 即使外部客户端崩溃或丢了任务密钥，用户也能在内置界面停下任何尚未结束的会话。公开的取消事件会注明谁取消了会话。
- 对别人建的任务，界面只能停下会话。批准、回答问题、追加指令、打断轮次和开新会话都由创建者处理。
- 任务只能由创建者关闭。取消全部会话后任务仍然打开，要另行关闭。关闭前所有会话都须已结束；关闭后仍可查历史，不能再开会话或重新打开任务。
- 「隐藏已关闭」和「只看我建的」只影响显示。界面用任务的 `createdBy` 区分内置界面和外部客户端创建的任务。
