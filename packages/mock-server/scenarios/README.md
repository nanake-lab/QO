# 模拟 harness 场景

`turn.start` 的输入以 `scenario:<名字>` 开头时选取同名 JSON 文件，名字后可以跟空格和说明。普通输入使用 complete。文件是依次发生的 harness 动作，mock 负责将它们转换为 QO 的事件和回调。QO-02 的测试适配器可以读取相同脚本。

| 场景          | 播放内容                                                         |
| ------------- | ---------------------------------------------------------------- |
| complete      | 两段助手文字、命令及输出、用量、结束                             |
| approval      | 命令审批。允许后产生脚本输出，拒绝后条目标记为中断，本轮正常结束 |
| file-approval | 文件审批带路径与差异。模拟修改仅更新内存条目                     |
| input         | 私有多题输入，包含选择题和保密题，收到回答后继续                 |
| slow          | 每秒一段文字，持续 60 秒，可随时打断或取消                       |
| fail          | harness 报错，轮次与会话进入失败终态                             |

每个文件是动作数组。`text` 追加文本，`delayMs` 是输出前的时延，`repeat` 是输出次数。`command/output` 或 `file/diff` 描述模拟操作及其结果，`approval: true` 表示执行前请求本次批准。`questions` 发起私有输入，题目 ID 在该请求内唯一。`usage` 给出本轮输入和输出 token 计数，十进制字符串保留精度。`end: true` 或 `fail` 结束轮次。命令和文件操作均为脚本数据。
